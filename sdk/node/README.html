wechat-use Node SDK

WechatUsePuppet 保留 Wechaty PuppetService API，修正 1.19.9 的定位反序列化。适用于 Node 18 及以上版本。

源码安装

配合本目录同一提交构建的 wechat-use gateway 使用。从仓库根目录安装：

npm install ./sdk/node --install-links

开发树中的目录位于 wx/sdk/node 时，将路径替换为 ./wx/sdk/node。发布包通过 GitHub Releases 分发，不发布到 npm registry。

接入 Wechaty

import { WechatyBuilder } from 'wechaty'
import { WechatUsePuppet } from '@wechat-use/client'

const puppet = new WechatUsePuppet({
  endpoint: '127.0.0.1:18401',
  token: process.env.WECHATY_GATEWAY_BEARER,
  tls: { disable: true, serverName: 'localhost' },
})
const bot = WechatyBuilder.build({ puppet })
await bot.start()

token 使用与网关相同的 bearer。无 TLS 仅用于本机；远程使用 TLS 及相应 CA 配置。激活码与网关 bearer 分开管理。

定位兼容性

上游 PuppetService 1.19.9 将 protobuf 对象直接展开，定位数值会保留默认的 0。此类使用同一已鉴权连接读取 protobuf getter，返回正确的 latitude、longitude、address、name、accuracy；消息不存在、无定位或传输失败时保留错误。

图片发送

import { FileBox } from 'file-box'
await puppet.messageSendFile('filehelper', FileBox.fromFile('/local/photo.png'))

标准 FileBox 本地文件和 Buffer 会经 Upload 转为 UUID FileBox。上传最多 64 MiB，5 分钟内有效；发送只允许领取一次。当前 gateway 的原生发送管线仅支持图片，普通文件、视频、卡片仍待接入。

messageSendFile 在发送失败或送达不确定时保留错误，不会像上游 1.19.9 那样尝试旧发送接口。不要在异常处理里无条件重发；先确认实际送达状态。

其余方法沿用 PuppetService。此兼容层固定依赖 1.19.9，升级依赖时须重新运行客户端契约测试。

客户端测试使用合成后台验证 gRPC 与标准 Wechaty 调用链。真实微信收发及未完成的网关能力，仍需按项目能力清单验收。
