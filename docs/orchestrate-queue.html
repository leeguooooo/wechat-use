Orchestrate 持久队列

收件、发送阶段和回执保存在本机 SQLite 队列。队列按配置中的 tenant、发件箱地址和 webhook 地址隔离；同一地址服务多个账号时，应分别配置 tenant。

处理规则

情况行为
微信未运行、进程在准备期间切换、发送租约不足不调用原生发送，保存可重试回执。SaaS 确认失败回执并再次分配任务后重试。
原生发送已经开始后超时或进程退出保留待核查状态，不自动重发同一任务。重复领取时重放已有回执。
发送已确认，ACK 网络请求失败持续重试持久回执，不再次发送微信消息。回执在网络请求之前落盘。
Webhook 网络错误、5xx、401/403、408/425/429保留原消息与幂等键，按退避或 Retry-After 重试。更新同一目标的凭据后可继续处理。
其他 4xx 或重定向保留为 rejected，保留消息内容，等待检查与显式重试。不会跟随重定向。
保留的未交付事件达到 10,000 条停止取新事件，不以驱逐旧记录腾空容量。已完成事件保留去重标记并清除存储的消息正文。

检查与恢复

wechat-use orchestrate queue list
wechat-use orchestrate queue scopes
wechat-use orchestrate queue --scope QUEUE_SCOPE list
wechat-use orchestrate queue retry-inbound EVENT_ID

列表默认只显示任务标识、状态、重试次数和错误，不输出聊天正文或凭据。旧目标的队列可以只读检查；重试必须使用匹配该队列的目标配置。

retry-inbound 只重新排入被拒绝的 webhook 事件，不直接发送微信。SaaS 必须按 X-Idempotency-Key 幂等处理重复请求。待核查的微信发送不会通过该命令重发。

升级与状态保留

旧 JSONL 回执首次导入时绑定目标队列，原文件保留。旧 done 回执缺少送达确认时，转为不可自动重试的待核查回执。更换目标地址或 tenant 后，不会把旧回执导入新目标。

队列数据库位于实例状态目录的 orchestrate-queues 子目录，文件权限为 0600。配置中的 bearer 与 webhook secret 不保存在队列中。

验证范围

16 项事务与 worker 恢复专项、74 项 Orchestrate 回归、22 项 SDK 回归通过；SaaS 模板的 43 项测试与 TypeScript 检查通过。测试包含真实本机 HTTP 请求和加密数据库夹具，外部 SaaS、真实微信收发及长期运行尚未验收。

当前可恢复已落盘的事件、任务和回执。断线期间尚未进入队列的源事件暂不自动补齐；源事件重放、真实环境持续运行及完整发布仍待验收。
