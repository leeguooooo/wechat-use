# CHANGELOG

正式发行版本以 [GitHub Releases](https://github.com/leeguooooo/wechat-use/releases) 为准。

## v1.18.7

- 设置窗口自动采集脱敏环境和后台状态，所有页面均可复制诊断；错误页显示固定问题代码，服务未启动时窗口仍能提供基本诊断。
- 提前检查系统开发工具授权，改用“授权并继续”打开 macOS 管理员确认，后台初始化不再等待终端密码。
- 保留初始化失败类别和退出状态，移除初始化错误的泛化重装入口；重试只处理本次结果，数据就绪后自动清理旧错误。
- 已登录账号的数据发现暂未就绪时，最多自动再试一次，不退出微信或清空密钥。

## v1.18.6

- 新增原生“微信工具设置”窗口，首次安装和后续恢复共用同一流程；可粘贴激活码、完成登录及拖拽授权，已完成状态自动复用。
- 后台服务在等待授权时保持可诊断；权限请求和初始化都由正式后台发起，避免借用终端权限。
- 统一选择兼容的已安装调试组件，避免旧 Xcode LLDB 在新系统上崩溃，不修改全局 Xcode 选择。
- 记录发送验证意图，取消、中断或结果不明时不自动重发；实际服务与发送结果才决定是否就绪。
- 后台会话切换不再把暂时为空的会话标识视为完成了一圈。

## 后台授权引导更新（2026-09-07）

- 安装器改由 launchd 启动工具程序申请权限，避免向终端申请控制电脑权限。
- 授权后自动刷新工具后台服务，并核验 bridge 和 daemon；保留微信登录和密钥。
- 去掉旧版手动修复命令，确认缺权限后直接进入引导，不再等待已知失败的健康检查。
- 旧授权有效时继续复用，不要求删除或全局重置授权。

## 安装脚本更新（2026-09-07）

- 修复旧 LaunchAgent 程序路径、PATH、禁用状态及日志目录，并保留自定义参数和环境变量。
- 显示真实的服务注册错误；服务不可用时不再误报权限缺失或建议直接发送消息。
- 终端 curl 安装确认缺权限后自动进入授权引导，必要时选中文件供拖拽，并在授权后继续核验。无需更新 1.18.5 二进制。

## v1.18.5

- 交互式 init 自动引导必要授权；打开系统设置并在 Finder 选中程序，支持拖入辅助功能列表，授权后自动复验。JSON 和脚本模式默认保持后台，可用 `init --fix-tcc` 显式引导。
- 权限申请及复验使用运行中的 wechatd，不再启动临时 wechatd，也不重启微信或清空其他应用授权。
- 安装器及发送失败提示提供相同引导，移除手动打开聊天、发送消息的建议。

## 2026-09-06 源码变更记录

以下为此前已合入源码的变更。具体功能及限制见各项说明；完整真机覆盖仍在继续。

### 收发结果与机器人恢复

- SDK 和机器人只在确认送达后报告发送成功。发送状态未确认、响应丢失或发送后超时，不再盲目重发；Wechaty 不再生成无法对应真实消息的随机消息 ID。
- Orchestrate 的收件、发送阶段和回执改为持久保存。消息已确认发送、但回执提交失败时，只重试回执，避免再次发送同一条微信。
- 按目标配置隔离任务队列；新增队列列表、详情、目标范围和入站重试命令。积压达到上限时暂停补读，保留尚未交付的事件。
- 网络异常和限流按退避或 `Retry-After` 重试；不能自动恢复的请求保留为待检查状态。默认检查输出不展示聊天正文或凭据。
- 断线或重启后继续补读未处理的新事件，处理同秒消息、迟到写入和新增历史分片。首次启用先建立历史基线，不批量推送旧聊天。
- 数据库替换后，能够识别的历史消息继续去重；无法确认是否重复的记录留待检查。旧回执升级时保留原文件，缺少送达确认的旧记录不会自动重发。

### Wechaty、SDK 与接入示例

- 补齐群枚举、成员、群名、联系人备注和头像等读取接口；修正私聊发送者识别，以及链接、名片、定位和小程序消息的字段解析。
- 历史消息查询可按消息 ID 读取数据库记录，不再只依赖最近消息缓存。
- 改善标准 PuppetService 客户端的鉴权兼容性，提供配套 Node 兼容客户端与 TypeScript 类型声明。
- Wechaty 引入事件补读和本地游标保存；客户端处理确认、页内断线恢复及完整多消费者续传仍待完成。
- 事件补读暂时失败时继续重试，仅在服务明确不支持补读时使用旧事件流。
- 图片发送支持标准 UUID FileBox 与 base64；本地文件和 Buffer 由客户端上传，服务端不接受任意本地路径。上传文件可分块下载，并按身份、账号隔离；每个文件上限 64 MiB，5 分钟内有效。
- 同一上传 ID 只允许一个发送请求领取；上传中断、失败、过期及发送结束会清理临时文件。配套客户端在送达不确定时不再调用旧接口重发。
- 普通文件、视频、卡片原生发送和历史媒体流式解密下载尚未完成，图片真实送达仍需验收。详见[媒体传输说明](sdk-media-transfer.html)。
- 更新 echo、群聊 @ 和 LLM 机器人示例，统一客户端配置、自消息过滤、账号隔离和发送失败处理。
- SaaS 模板接受完整的消息与好友事件类型，并保留来源账号信息。

### 读取与搜索

- 全局搜索可分别展开命中会话的上下文。相距较远的命中分别读取，避免较早消息的上下文被统一条数上限挤掉。
- 明确标记上下文截断、读取失败、来源过旧和原消息缺失；不同窗口使用独立连接，避免超时后的迟到响应混入下一次读取。
- 历史、监听和搜索索引统一正文读取规则：主正文字段为空时使用备用字段，缺少可选字段时仍可读取；损坏的压缩消息明确显示解压失败。
- 旧搜索索引升级后重新回灌正文，保留会话排除设置。首次回灌期间，搜索会提示索引尚未就绪。
- 增加升级读取对照工具，检查采样结果中的漏读、重复、顺序、正文、发送者和上下文变化；对照报告不输出私聊内容。

### 图片与归档

- 图片取回检查多个缓存和附件版本，按像素尺寸与校验结果选择。明确请求大图时，只有缩略图不会提前报告成功。
- 图片缓存校验实际文件内容，不再根据文件名推定 MD5 验证成功；较小图片不会覆盖已有的清晰缓存。
- 新增 `export --archive` 增量目录归档，支持 HTML、JSON、CSV 和 Markdown 分页输出。复用未变化的来源与页面，只更新受影响的输出。
- HTML 默认显示最新一页，其他页面按需打开。归档支持 `Ctrl-C` 和取消文件，读取错误或取消时保留上次完整结果。
- 支持 `--media` 收集本机可读附件，`--repair-media` 补回缺失项并检查图片升级。同一附件的多次引用合并记录，已有归档图片不会被较小版本降级。
- 丢失的页面可从归档状态重建；手工修改过的受管理文件不会被直接覆盖。微信本地清理历史后，已经归档的消息仍会保留。
- 归档只使用本机来源；未下载的附件需先在微信中下载。语音保存为原始 SILK 文件，不能从现有来源恢复的内容保留待补状态。

### 订阅与安装

- 改善已续订账号的本机凭据恢复，减少恢复后仍被要求重新激活的情况。
- 续订审批绑定申请时的目标，避免审批过程中误延长其他凭据。
- 调整工具微信图标的画布占用，并更新安装器对应资源的下载与校验。

### 验证边界

- 已有自动化与合成数据回归，不能据此认定完整 SDK 媒体链路、真实收发、外部 SaaS 和长时间运行均已验收。
- 后台发送准备、终端聊天、安装交互和订阅策略仍有进行中的改动，待合入后再补入正式条目；本节不承诺这些未合入内容已交付。
